Chatbot vs Agent — Đừng nhầm API key với API hub

Nhiều người nghe “kết nối API” tưởng là gán key vào config rồi xong việc. Nhưng có 2 kiểu kết nối hoàn toàn khác biệt:

  • Chatbot (plugin-based): Bạn cài plugin từng thứ một. OpenAI plugin → GPT gọi được GitHub. Claude plugin → gọi được Notion. Mỗi công cụ là 1 mối lẻ. Để làm 1 workflow (ghi chú → gửi email → lên lịch → báo cáo), bạn phải mở 3-4 cửa sổ, copy-paste dữ liệu qua từng bước. Nó không có bộ não điều phối — mỗi tool là 1 trợ lý độc lập, không nói chuyện với nhau.

  • Hermes Agent: Có API hub — 1 lớp middleware nội bộ, gom mọi key (OpenAI, Google, GitHub, Airtable, Telegram, Notion…) vào 1 mối. Bạn giao 1 mục tiêu (“hôm nay check pipeline bán hàng”), nó tự phân tích: Airtable có data → OpenAI sinh email → Notion ghi chú → Calendar lên lịch → Telegram báo về số. Tất cả trong 1 vòng lặp, 0 phút tay bạn can thiệp trung gian.

Theo Wikipedia, middleware trong kiến trúc phần mềm là: một lớp phần mềm cung cấp dịch vụ cho các ứ dụng, cho phép chúng giao tiếp và trao đổi dữ liệu — đúng như API hub của chúng ta: middleware giữa các dịch vụ đám mây.

Có 8 nguồn thật bao gồm Coasty (YC S26), Ox, Pizza Bot… Link thật, 0đ. Bước 3 — VIẾT (12 phút): Sinh ~1.500 từ theo cấu trúc (hook → agent vs chatbot → 8 bước → CEO command → số → FAQ → CTA). Với chatbot: bạn phải mở từng app, copy data, paste, check, deploy — từng bước. AI chỉ giúp 1 thao tác tại thời điểm. Với Hermes Agent: bạn như CEO — nói mục tiêu, delegate, nhận kết quả.

Setup API hub trong 5 phút (không code):

  1. Đặt key vào .env — OPENAI_API_KEY=, AIRTABLE_API_KEY=, GITHUB_TOKEN=, NOTION_TOKEN=, TELEGRAM_BOT_TOKEN=, GOOGLE_CREDS=, AIRTABLE_BASE_ID=

  2. Hệ thống đã load sẵn — config profile có section [api_hub] tự động load .env. Function web_search + web_extract trong .venv đã là API client sẵn. Thêm 2-3 wrapper cho Airtable/Notion/Telegram, bạn có API hub chạy hoạt động.

  3. Cron — chỉnh cron.schedule trong config, chạy mỗi 2 tiếng. Mỗi cron là 1 process con độc lập, không block nhau → đây chính là “phân thân” (Bài 31: 1 người giao 4 việc, 4 tiếng mất 1).

  4. Quality gate tự động — trước khi bất kỳ API nào được gọi, hệ thống chạy 10-check QA (đúng response format? số liệu có logic? không bị null?). Nếu lỗi → retry 2 lần rồi báo về.

  5. Bạn không cần biết code. Chỉ cần giao. web_search + web_extract đã sẵn. Thêm 3 wrapper cho Airtable/Notion/Telegram — agent kết nối 7 service. Như Bài 18: INPUT → OUTPUT (thay bạn nghĩ, tối ưu, đóng gói).

FAQ — 3 câu hỏi khi bạn thắc mắc

1. API hub khác plugin ChatGPT thế nào? Plugin ChatGPT chỉ là shortcut — bạn vẫn phải mở từng plugin, từng bước. API hub của Hermes là middleware: 1 lớp điều phối giữa các service. Bạn nói “pipeline hôm nay”, nó tự gọi 7 API theo thứ tự đúng logic, tự check lỗi, tự retry, tự báo cáo. Plugin không có “logic orchestrate” — chỉ có “gọi tool theo lệnh”.

2. Tôi có cần biết code không? Không. 7 service API hub của Hỉ đều chạy qua cron, 0 dòng code thêm từ bạn. Bạn chỉ cần biết set key vào .env. Hermes tự viết wrapper, tự gọi, tự quản lỗi. Như mẹo Bài 18 — INPUT→OUTPUT (thay bạn nghĩ, tối ưu, đóng gói).

3. API hub có an toàn không? Có 2 lớp bảo vệ: (1) key chỉ nằm trong .env local, không qua git — deploy qua API commit không bao giờ chạm tới key. (2) quality gate 10 điểm ở Bước 4: mọi API response phải pass check trước khi lưu/log. Kết quả: 0 leak trong 60 chu kỷ.
